开放API文档

1. 通用操作

开放平台提供了一种访问V8平台内部接口的机制。V8内部接口分为两种，一种是请求-响应模式的开放API，另一种是订阅-通知模式的开放事件。调用开放API可以使用平台提供的SDK，也可以自行书写代码访问。

1.1使用开放平台SDK

1：添加MAVEN依赖
<dependencies>
<dependency>
<groupId>com.seeyon</groupId>
<artifactId>cip-openapi-client</artifactId>
<version>2.0.0</version>
</dependency>
</dependencies>

2：请求示例：

public static void main(String[] args) {
    // V8开放平台请求地址
    String url = "[API_HOST]";
    // 每一个三方应用接入后分配的AppKey和AppSecret
    String appKey = "[REDACTED]";
    String secretKey = "[REDACTED]";
    // 每一个接口的具体访问路径
    String api = "/demo-order/order/query";
    OpenApiClient client = new OpenApiClient(url + api, appKey, secretKey);
    ApiSingleRequest request = new ApiSingleRequest();
    // 请求流水号。流水号相同的请求直接返回上次的结果
    request.setRequestId("abc" + System.currentTimeMillis());
    // 时间戳参数，和服务器时间相差5分钟以内
    request.setTimestamp(System.currentTimeMillis());
    // 拼接具体的业务参数
    Map<String, Object> dataMap = new HashMap<>();
    dataMap.put("name", "张三");
    dataMap.put("zjhm", "13134525");
    dataMap.put("certNumber", "cert_no_7");
    request.setData(dataMap);
    // 调用接口
    ApiSingleResponse response = client.send(request);
    // status为0表示请求成功；-1表示是异步请求，服务器正在处理；其他表示出错了
    int status = response.getStatus();
    // code是BOOT_0000表示业务处理成功，否则都是有问题的
    String code = response.getCode();
    // 处理有问题时，这个表示错误原因
    String message = response.getMessage();
    // 这个是真正返回的业务数据，一般来说是一个json字符串
    Object content = response.getData().getContent();
}

3：上面的例子是不分页的处理，有些接口返回是分页的，使用ApiPageRequest，ApiPageResponse接收。接口具体的请求参数参考帮助。

1.4 开放事件订阅和接收

在创建开放平台接入应用的时候，可以在【事件订阅】页签订阅V8内部的开放事件。

订阅时需要配置一个回调URL。当事件触发时，开放平台向该URL发送POST请求，传递事件的详情参数。订阅事件时可以额外配置两个可选参数进行安全控制：加密Key和回调Token。配置加密Key以后，事件的详情数据将用此key作为加密因子，进行AES加密传输，没有配置的话，就是明文传递；配置了回调token时，在POST请求的header中，会将此token原样传回。URL收到开放事件的通知后，可以进行如下的操作获取数据。

/**
 * 这个REST接口，用来演示接收开放事件的通知
 * 1：事件通知使用POST方式发送的，接收端必须支持POST请求方式
 * 2：收到事件通知请求后，需要返回200HTTP响应。其余响应码表示失败，开放平台会自动重发。重发的间隔越来越长，最多尝试10次。
 * 3：事件通知数据使用application/json格式发送
 * 4：事件通知的HTTP请求头里面，可以获得如下参数：
 * eventId：必有属性，回调的流水号。eventId一致，表示是同一个事件通知了多次
 * eventName：必有属性，事件名称。(事件名称是包含中文的，需要URL加解密)
 * eventKey：必有属性，事件标识，区分是什么事件。
 * createTime：必有属性，通知产生的时间
 * eventToken：可选属性。配置应用的事件回调参数设置的token，原样返回，没有设置就无此参数。开发者可以利用这个进行安全认证。
 * 5：如果配置事件回调的加密Key，那么事件回调的Json是加密的，只有一个属性encrypt，属性的内容是原始DTO的AES加密串;如果没有配置，那么json是原始的DTO。
 */
@SuppressWarnings("rawtypes")
@PostMapping("open-event-map")
@ResponseBody
public String openEventCallBack(HttpServletRequest request, @RequestBody Map map) {
    // 事件发生时间
    String createTime = request.getHeader("createTime");
    // 事件的流水号
    String eventId = request.getHeader("eventId");
    // 如果订阅事件时设置了回调token，可以获取token进行校验
    String eventToken = [REDACTED]"eventToken");
    if (!OpenApiGlobalConfig.EVENT_CALL_BACK_TOKEN.equals(eventToken)) {
        System.err.println("token不匹配，这是非法的请求！");
        return "error";
    }
    // eventName：事件名称，解码处理
    try {
        String eventName = URLDecoder.decode(request.getHeader("eventName"), StandardCharsets.UTF_8.displayName());
        System.err.println("收到事件：" + eventName);
    } catch (UnsupportedEncodingException e) {
        e.printStackTrace();
    }
    // 事件标识，可以用此字段区分是什么事件发生了
    String eventKey = request.getHeader("eventKey");
    if (!"".equals(OpenApiGlobalConfig.EVENT_CALL_BACK_KEY)) {
        // 如果设置了加密key，那么返回的数据是加密的，需要解密。加解密算法是AES算法。
        String encryptContent = (String) map.get("encrypt");            
        String realContent = OpenApiClient.decrypt(encryptContent, OpenApiGlobalConfig.EVENT_CALL_BACK_KEY);
        System.err.println("原始的JSON数据是：" + realContent);
        // 拿到原始的json串以后，可以json串转map或者转对应的DTO，继续处理
        Map dataMap = OpenApiUtil.fromJson(realContent, Map.class);
        // 后续处理。。。。
        System.err.println("事件真实数据：" + dataMap);
    } else {
        // 如果没有配置加密，那么是明文传输的，收到的Map就是真实的数据
        Map dataMap = map;
        // 后续处理
        System.err.println("事件真实数据：" + dataMap);
    }
    return "OK";
}
